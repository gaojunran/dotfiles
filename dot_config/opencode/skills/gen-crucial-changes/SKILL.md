## 步骤

为用户生成 HTML 报告。当本机有 caddy / nginx web server 的时候，应该把 HTML 报告挂上去并给用户提供链接。如果没有的话直接输出 HTML 文件地址即可。

关键变更代码的定义： 这部分代码的**逻辑**必须是新产生的而非已有的、且相对重要的、存在正确性风险的。

以下不属于关键变更代码：

1. 移动一部分代码到另一个文件、抽取函数逻辑等。它们本质上没有创造新的逻辑。
2. 注册设置项、i18n 条目等。它们逻辑很简单且属于杂活，没有让用户 Review 的必要。
3. 工具函数的封装等。它们本质上属于与项目本身关系不大的部分，作者不关注这些实现细节。
4. 测试代码。
5. 配置文件和文档变更。

报告内容需要包含：

1. 关键变更代码的完整 patch、必须包含每一部分**变动了什么、为什么这么写、为什么写在这里而不是写在其他位置、是否已经是最简单的实现**。这里的每一部分粒度应该尽量小，比如函数级，大函数还要分成几个部分。
2. 非关键变更代码的逐文件 patch。
